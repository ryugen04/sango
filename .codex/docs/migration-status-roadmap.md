# Migration Status and Roadmap

この文書は、移行作業の現状と次フェーズを、project 固有情報を含めずに管理するための正本です。

## 記述ルール

- 個人名、組織名、絶対パス、秘匿情報は書かない
- 固有環境に依存する値はプレースホルダで表現する
- 実装状況は「完了」「未完了」「次アクション」で管理する

## 未完了項目の具体化

### 1. 旧運用資産の再利用設計

- ゴール: 旧アシスタント設定や YAML を、再利用可能な形だけ抽出する
- 出力物1: 汎用テンプレート群（規約、チェックリスト、雛形）
- 出力物2: 共通ロジックのライブラリ化候補一覧
- 出力物3: 非移植対象の明確化（秘匿情報・環境依存情報）

### 2. troubleshoot カタログ運用

- ゴール: 障害知見を「実行可能な診断」と「人が読む runbook」に分離して管理する
- 出力物1: troubleshoot カードのテンプレート
- 出力物2: 追加・更新・廃止のライフサイクル
- 出力物3: 検証日（last verified）の更新ルール

## 次フェーズ計画

1. 資産分類フェーズ
- 既存資産を `template` / `library` / `non-portable` に棚卸しする
2. 標準化フェーズ
- 汎用テンプレートを最小単位で切り出し、適用条件を定義する
- ライブラリ候補は API 境界（入出力・責務）を固定する
3. 運用定着フェーズ
- troubleshoot カード運用を開始し、更新履歴を残す
- 定期的に `audit inventory` と verify を実行する

## 移行完了判定

以下をすべて満たしたら、移行計画を close してよい。

- 再利用対象が `template` と `library` に分離されている
- 非移植対象（project 固有情報）が明文化されている
- troubleshoot カードが運用され、少なくとも 1 回更新サイクルを回している
- verify / CI / release の標準導線が継続利用されている
